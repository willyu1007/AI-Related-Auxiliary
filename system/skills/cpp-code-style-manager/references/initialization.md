# 初始化与维护

管理技能负责流程编排；共享 CLI 保持非交互且具确定性。

## 状态机

在检查规则之前，针对明确的项目根目录和用户主目录运行 `status`。

- `missing`：进入该层的初始化阶段。
- `invalid`：停止流程并报告路径及校验错误；不得将其当作缺失文件覆盖。
- `empty` 和 `valid`：都视为已初始化。
- 三层都已初始化时，返回 `ready: true`。
- 本地规则包目录中存在可用的 bundled 规则包新版本时，仅提供提示，不阻塞当前工作。

每层都要单独生成提案并单独确认。用户取消时，在后续层之前停止，并保留已确认的前置层。`.clang-format` 是单独展示的项目目标，即使它被包含在提案中也一样。

## 有序初始化

1. 检查系统、用户和项目路径。
2. 系统层缺失时，默认推荐 Google，也可以使用用户选择的自定义来源。展示 profile 元数据、覆盖范围、基础样式、规则、来源、目标路径和影响范围。只有审查后确认，才能应用。
3. 用户层缺失时，围绕长期个人偏好进行沟通。只保存用户明确表达的偏好，不复制系统默认规则。确认空文件表示没有用户覆盖规则。
4. 项目层缺失时，按以下顺序检查证据：用户当前决定、仓库明确的文档/配置、项目自有 C++ 代码中的重复模式。排除第三方、生成物、缓存和外部引擎代码。展示代表性证据和未决决定。确认空文件表示没有项目覆盖规则。
5. 校验三层并报告最终生效来源和覆盖链。

后续运行中，`upgradeAvailable` 只用于建议 bundled 规则包候选版本。展示差异并要求新的提案确认；不得自动升级，也不得阻塞已就绪的工作。

修改、禁用、删除或学习规则时，展示最终完整规则内容、准确的目标层级、来源、覆盖影响和写入路径。当前任务中的纠正只改变候选内容，不代表允许持久化。
