# Reorganize the private operations document

Use only when the user requests whole-document organization or conversion. This authorizes document maintenance, not live changes, account creation, credential rotation, or new permissions.

1. Check the actual file, confidentiality, tracking, and any symlink destination. Inventory its sections without printing credentials. Identify shared resources, duplicate statements, references, and facts whose current status is uncertain.
2. Create an exclusive, uniquely named sibling backup such as `sensitive-ops.md.bak-<timestamp>-<suffix>`, outside version control, with owner-only access and no broader permissions than the original. Never overwrite a prior backup. Record its path without reading its secrets into output.
3. Build the candidate in the same private directory with equally restrictive permissions. Organize current objects using the main skill's rules. Preserve secret bytes, valid endpoints, stable identifiers, supported mappings, and operationally necessary commands. Preserve any existing helper workflow/completion markers and the unique pending placeholders they track; do not merge or rewrite them as narrative cleanup. Do not change a value merely to make entries look consistent. Keep unresolved conflicts explicitly unverified; do not invent references to a secret store as a substitute for a sole-copy secret.
4. Separate durable facts from obsolete narrative. Replace generic tutorials with existing, verified repository references, retaining private overrides and recovery steps not covered there. If a necessary guide is missing, retain the useful instructions rather than inventing a reference. Keep uncertain facts as 待核实 at their object; do not copy private material into a repository as an archive.
5. Compare the candidate against the original in memory. Check that every credential-bearing entry and needed object is preserved or has an evidenced replacement/removal, references resolve, shared values are not duplicated, and no permissions or environment associations changed. Emit counts, field paths, and decisions, never a raw diff containing secrets.
6. Recheck that the source has not changed since the inventory. Atomically replace it only after validation; otherwise preserve the original and reconcile the concurrent edit. Preserve its permissions. Verify the written content and remove temporary candidates that contain private material.
7. Report the organization, unresolved fields, verification limits, and backup path. Default to retaining this one backup until the user accepts the reorganization; state that expiry condition. Do not delete earlier backups or imply their retention is indefinite.
