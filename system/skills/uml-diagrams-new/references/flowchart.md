# 流程图

- Mermaid：`flowchart TD`（主链竖排）
- 示例：`examples/fig-control-flow.mmd`
- 布局 preset：[flowchart-default.json](../layouts/flowchart-default.json)

## 语义

> 修改边界见 [SKILL.md](../SKILL.md)「三层与修改边界」：本节仅小幅调整；**拆图、折返双列、增删步骤、合并主链**属于**布局**，须在布局步骤改 `.mmd` 并重跑转换，不得在转换后/MCP 硬凑。

- 起止：`([开始])`、`([结束])` 扁圆；不用 `(( ))` 实心圆
- 判断：`{是否…}` 菱形；**一步一框**
- **主链**：节点在源码中按执行顺序**从上到下**声明
- **主路径边**：「是」或继续主流程 → 指向**下一个主链节点**（视觉向下）
- **分支边**：「否」或例外 → 指向侧向步骤或汇合终态
- **汇合**：多条分支进同一终态时，**显式连到同一节点 id**（如 `end`）
- 条件：`A -->|是| B`、`A -->|否| C`

## 布局

本节的拆图、折返双列、合并步骤、增删框与 `subgraph` 分栏均属**布局层**；改完后须重新 CLI → Ungroup，再执行「转换后」。

- Mermaid 一步转换通常**不再**跑 `--layout`
- Ungroup 后若间距/平行边问题：`flowchart-default.json`（含 `mxParallelEdgeLayout`）
- 竖长单栏导致贴 Word 超高时：优先评估 **折返双列**（见下）或 **拆图**（见下），不要删 ELK 指望压矮

## 拆图规范

**何时拆**：主链 **>8** 步、满版心宽贴入后 `H_doc > 22–24 cm`，且折返双列仍超高或分支过重。

**切分位置**

- 沿**语义步骤**切，切点必须是真实流程步骤（如「是否更新跟踪集合＝是」→ 下一步「是否允许调整跟踪」）。
- **禁止**用与切点无关的节点名作「桥」（例如把后段的「调整集合」写在上图末尾、下图却从「是否允许调整」开始）。
- 上图保留的「否→结束」只覆盖**上图范围内**的退出；下图不再重复上图已结束的路径。

**每张图的结构**

| 规则 | 说明 |
|------|------|
| 上图 | 保留 `([开始])`；末尾用 **接续节点**（见下），**不要**第二个完整主链 |
| 下图 | **禁止**再用 `([开始])`；入口即切点后的第一步；图题注明「（续）接上图 ××」 |
| 结束 | 下图保留 `([结束])`；上图若含提前结束，**结束放在主链下方或侧向**，避免所有「否」指到图**右上角**同一结束（易触发 Mermaid 横排） |
| 接续节点 | 扁圆或细框，文案如 `([续下图])` / `[[续]]`；图题写清对应下图编号 |

**禁止**

- 两张图各写一套「开始…结束」却无语义接续；
- 上图末尾写子程序形 `[[某步骤名]]` 但下图入口不是该步骤的**直接后继**；
- 为压高度而拆图，却仍在每张短子图里让多条「否」汇到**上方**同一 `结束`（布局会乱，参见折返/拆图后的 Ungroup 微调）。

**拆图后 QA**

1. 读者能否不看正文就知 A→B 接续关系；
2. 每张单独估算 `H/W`，均应能在一页内满宽或限高贴入；
3. 再跑「转换后」端口与标签检查。

## 折返双列（单图不拆时的替代）

版心**宽度有限、高度超一页**，但希望**保留同一图号**时：可把主链拆成**左右两栏竖排**，用一根**折返边**连接——**左栏最下步 → 右栏最上步**，路径为：自左栏节点**下出** → **横向** → **上入**右栏首节点（Visio 式「蛇形」排版）。

**适用**

- 主链长、**侧向分支少**（或「否→结束」已在栏内底部汇合）；
- 折后估算：单栏 `H/W > 2`，双栏后整体 `H/W ≈ 1–1.6`，满版心宽可一页贴入；
- 需要连续图号、不宜 4-1a / 4-1b 时使用。

**不适用**

- 大量「否」跨栏汇到同一结束（线会横穿两栏，可读性差）→ 用拆图或把 `结束` 固定在**整图最下**；
- 右栏主要是独立侧支而非主链延续。

**Mermaid 写法（语义）**

用两个 `subgraph` 表左右栏，**显式**写栏间边；栏内仍 `direction TB`：

```mermaid
flowchart TD
  subgraph colL[" "]
    direction TB
    start([开始]) --> a[步骤A] --> b[步骤B] --> bridgeL[步骤C]
  end
  subgraph colR[" "]
    direction TB
    bridgeR[步骤D] --> e[步骤E] --> end([结束])
  end
  bridgeL --> bridgeR
```

- `colL` / `colR` 标签宜留空或极短，避免占宽。
- 主链步骤按顺序**先填满左栏、再填右栏**；`bridgeL --> bridgeR` 即折返边。
- 左栏内的「否→结束」尽量指向**左栏下方**的 `end` 或共享的**整图底部** `end`，不要指到右栏上方。

**转换后（折返边）**

Mermaid 转换器未必自动「下→横→上」。Ungroup 后检查 `bridgeL → bridgeR`：

- 出口：左栏末节点 `exitX=0.5;exitY=1`（或 `exitX=1;exitY=0.5` 若从右侧折出）；
- 入口：右栏首节点 `entryX=0.5;entryY=0`；
- 必要时加 `Array as="points"`：左栏底中点 → 两栏间隙中点（横向）→ 右栏顶中点。

**与拆图的选择**

| 情况 | 建议 |
|------|------|
| 要同一图号、主链长、分支轻 | **折返双列** |
| 两段语义相对独立、分支重 | **拆图**（遵守上一节） |
| 折返后 `H/W` 仍 > ~1.6 | 合并步骤或改为拆图 |

## 样式

| 项 | 值 |
|----|-----|
| 填充 / 框线 / 连线 | `#ffffff` / `#333333`，`strokeWidth=2` |
| 文字 | `#000000`，Microsoft YaHei，框内 `fontSize≥14`，边标签 `≥13` |
| 边 | `edgeStyle=orthogonalEdgeStyle;rounded=0;endArrow=block;endFill=1` |
| 边标签 | `labelBackgroundColor=#ffffff` |

Ungroup 后批量检查：边的 `rounded=1` → `rounded=0`。

## 转换后

Mermaid 无法声明菱形端口；**Ungroup 后**用 draw.io 或 MCP：

| 问题 | 处理 |
|------|------|
| 分支线应从菱形顶点出 | 主链：`exitX=0.5;exitY=1;entryX=0.5;entryY=0` |
| 左右偏好分支 | 分支：`exitX=1;exitY=0.5` 或 `exitX=0;exitY=0.5` |
| 「是/否」离菱形远 | offset：主链 `y=10`；分支 `x=10,y=-6` |

## 贴进文档（可选）

**仅当用户明确图将嵌入 Word/PDF 等时执行本节。**

### 导出

```powershell
$drawio = & powershell -NoProfile -File scripts/find-drawio.ps1
& $drawio -x -f png -e -b 10 -s 3 --crop -o name.drawio.png name.drawio
```

导出前 **Fit Page to Content**；画布宽度目标 **700–1200 px**。

### 宽高比：优先改图

竖排主链易 **H/W > 2**。Word 等比缩放：`H_doc = W_doc × (H/W)`。

**在布局层改 `.mmd` 拓扑/排版**（见 SKILL「三层与修改边界」），不在 Word 里只压宽度，也不在 draw.io 里只拖节点：

| 优先级 | 做法 | 见 |
|--------|------|-----|
| 1 | **折返双列**（单图、左右栏 + 下→横→上折返边） | 上文「折返双列」 |
| 2 | **拆图**（两张、语义接续） | 上文「拆图规范」 |
| 3 | **合并步骤** / 子流程节点压缩主链 | 语义节 |
| 4 | **略减间距** | `flowchart-default.json` |

主链 **>8** 步：必须先估算 `H/W`，在折返双列与拆图之间二选一（或组合：折返仍超高再拆）。

**不推荐**：删 ELK 但不改拓扑；Word 只设最小宽度不算高度。

### 贴文档前 QA

1. 估算满宽贴入后高度是否 ≤ 一页（约 22–24 cm）
2. 菱形端口、标签贴靠、无圆弧边
3. 在 Word **实际显示 cm** 下字可读
