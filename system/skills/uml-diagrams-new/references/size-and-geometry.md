# 最终尺寸与几何验收

生成前确认尺寸是否受约束。有要求时记录放置宽度 W、可用高度 H、纸张/屏幕方向和最小实际字号；不知道文档版心时向用户确认。没有要求时不以固定 700–1200 px 作为验收条件。

## 适配顺序

1. 裁切画布空白（Fit Page to Content / crop）；不得裁掉内容。
2. 评估等比放置：图宽 w、高 h，以 W 放置后 `H_doc = W × h / w`。字号同样按比例变化。毫米宽度可换算为点：`字号_pt = 图内字号 × W_mm × 72 / 25.4 / w`。需同时满足高度和最小字号；PNG 导出 `-s 3` 增加像素，不改善实际放置字号。
3. 调整 LR/TB 方向、间距、节点宽度和文字换行，减少过长标签；不改变含义。时序图保持参与者与时间顺序。
4. 评估分栏、折返或分组；明确阅读次序，检查跨栏连线。它们仍是一张图，不等于拆图。
5. 若仍不能放入尺寸且保持可读，按职责、阶段或场景**语义拆分**，每张独立验收。

## 明确拆分含义

- **横向拆分**：图太宽，按职责/模块/参与者域拆成几张更窄的图。例如整体关系总览 + 各模块详图。不会直接把图片沿竖直线切开。
- **竖向拆分**：图太高，按阶段/子流程/消息区间拆成几张更短的图。例如校验、执行、结果三个阶段。不会直接把图片沿水平线切开。
- 每张保留标题、必要上下文和稳定编号；跨图引用用“接续 A / 见图 X”及清晰输入输出。同一参与者/节点保留同名；需要在多张出现时说明是上下文重复。
- 记录拆分清单，逐项核对原节点、关系、条件和消息都有归属。不能通过删除、隐藏、合并不同含义元素或非等比拉伸满足尺寸。

## 检测和修复闭环

在每次最终字号、换行、尺寸、标签位置或路由调整后：

1. 从当前 draw.io 重新导出带嵌入源的 SVG（`-x -f svg -e`），运行几何检查。报告中的页、cell ID、文字和碰撞区域定位元素。
2. `label-label` / `edge-label`：调标签 offset、换行、标签间距或路由；自身边标签覆盖自身线是合法关系。
3. `label-node` / `node-node` / `edge-node`：调局部节点间距、端口、路由；必要时明确运行类型修复 preset。保持合法容器关系。
4. `text-overflow` / `text-clipping` / `canvas-overflow`：扩大可用区域、换行、修复裁切或重新 fit content，不能隐去文字。
5. 普通交叉/共线是警告，结合阅读路径检查；错误必须修复。coverage gap 是未完成验收，不是无错误。
6. 重导出、重测量；不用旧 SVG 或旧通过报告。最后在实际放置尺寸下目视检查文字、箭头、连线端点及 UML 语义。

第一版只读检测，不运行自动标签求解或全图重建。未知 shape、复杂时序片段等出现缺口时先明确支持范围，不用纯 AABB 代替实际轮廓验收。
