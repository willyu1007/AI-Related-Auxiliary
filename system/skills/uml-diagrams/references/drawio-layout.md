# draw.io 技术图布局规范

生成或修订 `docs/model-docx/<MODEL_CODE>/media/*.drawio` 时须遵守。目标是：**印进 DOCX 后仍像 Visio 工程图**——线清晰、起止明确、文字在框内、箭头一致。

完整审查策略见 [UML 视觉质检框架](references/uml-visual-qa-framework.md) 与 [按类型检查清单](references/uml-visual-qa-by-type.md)，本页仅给出样式与布局规则的落地要求。

视觉语言按图类分层（A3）：

| 图类 | `figure_type` | 视觉语言 |
|---|---|---|
| 主流程图 | `flowchart` | **Visio 流程图**：扁圆「开始/结束」、圆角处理、菱形判断、实心三角箭头 |
| 状态机 | `state` | **Visio 状态图**：扁圆「开始」、圆角状态、转换箭头；「关机」是工作状态，不是终态 |
| 类图 | `other`（模块类图） | **UML 类图**：类名 / 属性 / 操作三栏，禁止把职责说明堆进一个大框 |
| 时序图 | `sequence` | **UML 时序**：生命线 + 实心块箭头；回传同样 `endArrow=block` |
| 结构/部署 | `architecture` | Visio 组件/部署风：矩形框、正交连线、统一线宽 |

## 线宽、颜色、箭头与画布（所有图类）

Word 版心约 **146 mm**。画布过宽时 1 px 线会被缩到看不见。

- 框线 `strokeWidth ≥ 2`，连线 `strokeWidth ≥ 2`（大结构图可用 3）。
- 框线颜色 `#355E8D`，连线颜色 `#333333`；**不要**用浅灰 `#5F6B75` / `#666666`。
- 流程/状态/结构/时序方向边统一 `endArrow=block;endFill=1;startArrow=none`。时序生命线保持 `endArrow=none;dashed=1`，不要加箭头。
- 字体 `Microsoft YaHei`；框内 `fontSize ≥ 14`，边标签 `≥ 13`。
- 框内留白 `spacing ≥ 6`；长文先加高/加宽，禁止文字贴边或溢出。
- **画布尽量收在 700–1200 宽**。模块结构图不要无谓撑到 2000+。
- **`pageHeight` / `pageWidth` 须贴近内容外框**。画布比节点高出一大截时，离线栅格化和 Word 插图都会在下方留白，流程图被压得很小。
- 导出 PNG 默认 `export_scale = 3`，并裁掉四周空白（draw.io CLI `--crop`，离线栅格化按非白像素裁剪）。提高倍率不能代替加线宽和收画布。
- 边标签必须 `labelBackgroundColor=#FFFFFF`，放在正交折线旁，不要单独做过窄的文本节点（如宽 32 px 的「是/否」）。

批量只改样式、不改坐标时：

```powershell
python .agents/skills/model-docx/scripts/normalize_drawio.py `
  "docs/model-docx/<MODEL_CODE>/media"
```

## 标注与连线

- 所有带文字的标签（边标签、条件说明）须设置 `labelBackgroundColor=#FFFFFF`；必要时加 `labelBorderColor=none`。
- 标签不得压在线上：用 `mxGeometry` 的 `mxPoint as="offset"` 偏移，或把标签放在正交折线的水平段/竖直段旁。
- 多条转换/消息走**不同通道**：开始/停止、超时、关机等路径分层（上/中/下或左/右），禁止共用同一竖直通道。
- 优先 `edgeStyle=orthogonalEdgeStyle` + 明确 `Array as="points"`，少用默认直线/曲线叠在一起。
- **请求与响应须分通道**：同一对节点间的实线请求与虚线响应不得共用同一 `y` 或同一竖直 `x`；响应优先走模型下方或外侧绕行。
- **返回消息箭头**：时序图/部署图中的回传边统一 `endArrow=block;endFill=1`；`endArrow=open` 在 draw.io CLI 导出 PNG 时易出现箭头缺失或方向异常。

## 画布与间距

- 状态机、时序图等关系多的图适当放大 `pageWidth` / `pageHeight`，但先加间距，再考虑加画布；不要先把画布拉到 2000+。
- 时序图生命线索引加宽；长横线消息走「上方/下方绕行」折线，避免标签压在生命线上。
- 类图属性/方法区高度随内容增加，避免末行贴边。
- **运行部署图（7.1 类）**：平台泳道与组件泳道之间须保留足够竖向间隙（建议 ≥ 60 px）；传感器等外部节点宜下移至组件泳道下方，为「查询上行 / 响应下行」留出独立通道。

## 按图类型的布局要点（易错）

### 模块结构 / 模块关系组件图（3.4、5.1，`fig-module-structure`）

| 易错点 | 现象 | 处理 |
|---|---|---|
| 边 `source`/`target` 与节点 `id` 不一致 | 节点都在、**连线全部消失** | 改 `.drawio` 或模板脚本后，逐条核对 `source`/`target` 是否对应现有 `mxCell id` |
| 从兄弟模型复制后只改节点文本未改 `id` | 同上；常见于 HWTZ→GDTZ（`rcs`/`modIr` 未改为 `opt`/`modOpt`） | 同步替换节点 `id` 与全部边的 `source`/`target`；`_gen_drawio.py` 等生成脚本须一并更新 |
| 双向边共用中心直线 | 标签与箭头叠压 | 一条走模块上方、一条走下方，或一条实线、一条虚线且 `y` 分层 |
| 画布过宽 | Word 里线细到看不见 | 改为 2～3 行模块网格，`pageWidth` 控制在约 1100 以内；连线 `strokeWidth ≥ 2` |

### 运行部署与调度关系图（7.1，`fig-run-composition`）

典型结构：上层「仿真系统」泳道（实例管理、步进调度、组件查询通道、宿主实体）→ 中层「目标特性组件」泳道（控制模块、解算模块）→ 下层「传感器」。

| 易错点 | 现象 | 处理 |
|---|---|---|
| 传感器→查询通道走平台层高度 | 「光电特性查询」水平段在 **y≈90–140** 穿过「实例管理」「步进调度」 | **禁止**在平台节点带内做长水平段；改走**左侧边距**（如 x=30）上行至平台底与组件顶之间的**间隙**（如 y≈230），再水平至「组件查询通道」中心，最后短竖线接入 |
| 查询与响应共用同一高度 | 虚线查询与虚线响应在模型区域重叠 | 查询：左侧上行 + 间隙层水平；响应：自解算模块**下方**（如 y≈510）水平至传感器 |
| 平台→控制模块多条边同 `y` | 初始化/步进/转发查询三线叠压 | 分层路由（如 y=190 / 205 / 220），各用独立 `Array as="points"` |
| 宿主→解算模块穿模 | 「宿主位姿」穿过组件框或与其他边交叉 | 从平台**右侧**绕行（如 x=985→920）再进入解算模块 |
| 组件泳道过矮、传感器过高 | 内部回传边（如「查询完成」）与「触发解算」争用同一区域 | 加大组件泳道高度；模块间回传走模块**下方**水平段（如 y≈430） |
| 框/线无 `strokeWidth` | 导出后线条发虚 | 框与连线均 `strokeWidth ≥ 2`，连线色 `#333333` |

**推荐路由（传感器 → 组件查询通道）**：

```text
传感器 → 左缘 (x≈30) → 上行至间隙层 (y≈230) → 水平至查询通道中心 (x≈615) → 短竖线接入查询通道
```

间隙层 `y` 须满足：**高于**平台泳道下沿、**低于**组件泳道上沿，且与平台→控制模块下行线（y≈190–220）错层。

### 主流程图（3.3，`fig-process-flow`）

主流程图采用 **Visio 流程图**起止图元，不是 UML 活动图黑圆/双圆。

| 图元 | draw.io 样式要点 | 说明 |
|---|---|---|
| **开始** | `rounded=1;arcSize=50;…strokeWidth=2;fontSize=14`，`value="开始"`，约 **140×50** | Visio terminator（扁圆）；文字仅为「开始」 |
| **结束** | 同上，`value="结束"`，约 **140×50** | 各分支须汇入结束节点 |
| 处理 | `rounded=1;arcSize=12;…strokeWidth=2` | 业务步骤写在圆角矩形内，文字居中不溢出 |
| 判断 | `rhombus;…strokeWidth=2` | 条件名写在菱形内；「是/否」放在**边标签**上 |

也允许 `shape=mxgraph.flowchart.terminator` 或足够大的椭圆（宽 ≥ 80、高 ≥ 36）写「开始」「结束」。

| 易错点 | 现象 | 处理 |
|---|---|---|
| 用 UML 实心黑圆 / `endState` 作流程起止 | 读者觉得不像 Visio，起止无字 | 改成扁圆 terminator，文字「开始」「结束」 |
| 开始/结束写成「开始本仿真步」等长句 | 扁圆装不下，文字出框 | 扁圆只写「开始」「结束」；触发语义放进首个处理框 |
| 「是/否」做成 32 px 文本节点 | 字漂在框外或压线 | 改为边的 `value` + 白底标签 |
| 多入口无汇合 | 失败/否分支悬空 | 各分支须汇入「结束」 |
| 画布过高过宽、线宽 1 | Word 里线看不清 | 收紧间距；连线 `strokeWidth ≥ 2` |

**推荐结构**：

```text
(开始) → [消费方发起查询 / 接收步进] → 判断/处理链 → … → (结束)
```

`validate` 会对 `figure_type: flowchart` 的 draw.io 检查是否存在上述 Visio 起止图元。`_modify` 构建为兼容旧稿可暂不阻断，但新绘流程图必须符合本表。

### 状态机（3.3，`fig-state-machine`）

| 图元 | 样式 | 说明 |
|---|---|---|
| 开始 | 与流程图相同的扁圆 terminator，`value="开始"`，约 **140×50** | 不要用无文字实心黑圆 |
| 状态 | 圆角矩形，`fontSize ≥ 15` | 状态名居中 |
| 终态 | 扁圆「结束」或 `endState` | **仅当对象销毁/卸载时使用**；「关机」是工作状态，不要误标成终态 |
| 转换 | 正交折线，`endArrow=block`，**边标签**白底分通道 | 同一对状态的往返边左右分槽；标签写在边上，不要单独做漂浮文本节点 |

四态（关机 / 待机 / 侦收 / 故障）推荐布局：

```text
     (开始)
        ↓
     ┌关机┐ ←──────── 左槽：故障→关机（标签在竖段中部）
        ↓ 初始化
     ┌待机┐ ←── 右远槽：待机→关机
        ↓ 开始侦收
     ┌侦收┐ ←── 右近槽：侦收→待机
        ↓ 设备或数据故障
     ┌故障┐
```

- 主链自上而下居中，不要把「开始侦收」绕到左侧。
- 回边贴框分槽（距框约 80–120 px），禁止拉到画布边缘造成大片空白。
- 同一状态框的多条侧边须错开锚点（上/下三分点），禁止进出共用一个中点，否则 PNG 里会看成一条线分叉。
- 「初始化或关机」必须贴在故障→关机竖段中部，不得漂在画布左上角。

### 模块类图（5.x，`fig-module-*-class`）

使用 UML 三栏类框，不要用 swimlane 把「职责/属性/操作/输出」写成一篇说明文。

```text
┌──────────────────────────┐
│  模块中文名               │
│  （程序标识）             │
├──────────────────────────┤
│  属性…                    │
├──────────────────────────┤
│  操作()…                  │
└──────────────────────────┘
```

- 类名用中文名。属性写可见性、名称和类型，如 `+ 扫描扇面: 度`。操作写可见性、名称、参数类型和返回值，如 `+ 周期探测(仿真时间: 秒): 观测结果`。
- 框高随行数增加；`fontSize ≥ 14`，左右留白，禁止出框。
- 继承用空心三角（`endArrow=block;endFill=0`），依赖用虚线开口箭头，组合用菱形，普通关联用实心块箭头。同一类框发出的多条边必须错开 `exitY`，禁止从同一个点分叉。

### 运行控制时序图（7.2，`fig-run-control-seq`）

| 易错点 | 现象 | 处理 |
|---|---|---|
| 响应消息缺独立边或箭头样式错误 | 「查询响应」箭头不显示或方向反 | 为「解算→控制→平台/传感器」补全回传边；统一 `endArrow=block` |
| 请求/响应同层 | 多条水平消息叠在一起 | 按生命线索引分层（如 y=470 / 530 / 600），`alt` 框内条件文字不与分隔线重叠 |
| 生命线索引过窄 | 标签压线 | 加宽列距；长消息走生命线上方或下方绕行 |

### 从模板 / 兄弟模型适配

- 复制 `media/*.drawio` 或运行 `adapt_from_*.py`、`_gen_drawio.py` 后，**必须**检查：节点 `id`、边 `source`/`target`、图题/节点文案是否一致。
- 手工修过的 `.drawio` 可能被再生成脚本覆盖；修复应回写**源模板或生成脚本**，避免下次生成回退。
- 同一 basename 的 `.drawio` 与 `.png` 须同步更新；`validate` 若提示「PNG 早于 draw.io 源文件」，须重新导出后再 `build`。

## 自检（导出 PNG 后）

1. 目视检查：标签是否被线穿过、箭头是否遮挡文字、是否有未连接的 stray 线段；**线在 Word 目标尺寸下是否仍清晰**。
2. 状态机：同一对状态间的「进入/退出」标签是否分离；起止是否为 Visio「开始」，而不是大黑点。
3. 时序图：`alt` 框内条件文字是否与分隔线重叠；**回传箭头是否完整可见**。
4. **模块结构图**：各模块间是否均有预期连线（尤其复制适配后）；画布是否过宽。
5. **运行部署图**：传感器→查询通道路径是否**避开**平台层「实例管理」「步进调度」等节点；查询/响应是否分通道。
6. **平台→组件下行线**：多条边是否分层、不与传感器上行线交叉。
7. **主流程图**：是否有 Visio「开始」「结束」扁圆；各分支是否汇入结束；是/否是否在边标签上。
8. **类图**：是否为三栏 UML；文字是否在框内。

## 与构建的关系

- 源文件为 `.drawio`；`build` 嵌入同名 `.png`。
- 修订 draw.io 后须重新导出 PNG，再 `validate` / `build`。
- 纳入 [主流程 §6 重绘并链接技术图](../SKILL.md)：**导出 PNG 后目视自检**，复杂图不通过则不得交付。
- 正式 JSON 与 `_modify` **共用同一套 media**；改图两边都会变。
- 交付前需同时通过 [UML 视觉质检框架](references/uml-visual-qa-framework.md) 的三层闭环（尤其 CRITICAL/ERROR 项）。

## 纳入 SKILL 的检查清单（摘要）

| 图类型 | 必查项 |
|---|---|
| 状态机 | Visio「开始」扁圆；主链居中；回边贴框分槽；转换用边标签 |
| 时序图 | 生命线索引足够宽；长消息绕行；`alt` 条件不与分隔线叠压；回传边 `endArrow=block` |
| 模块结构/组件图 | 边 `source`/`target` 与节点 `id` 一致；模块间连线可见；画布不过宽 |
| 运行部署图（7.1） | 传感器查询不走平台节点带；查询/响应分通道；平台→控制分层；线宽 ≥ 2 |
| 主流程图（3.3） | Visio「开始」「结束」扁圆；各分支汇入结束；是/否在边标签；线宽 ≥ 2 |
| 类图 | UML 三栏；字不溢出；`fontSize ≥ 14` |
| 组件/流程图 | 边标签白底且偏移；不与连线叠压 |
