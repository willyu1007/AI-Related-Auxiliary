# UML 图按类型检查清单（model-docx）

以下仅列关键强校验项，适配 `uml-visual-qa-framework.md` 三级质检体系。

## 通用图

- 文字居中、标签完整；
- 边标签有白底并避开主线；
- 关键关系保留方向，不用单色弱化语义；
- 同一节点发出的不同关系使用不同锚点；
- 一个节点只含一个对象或一个步骤，不把多项语义叠进同一个框；
- 同类形状风格一致。

## UML 类图（`figure_type=class` / `other`）

- 类名、属性、操作三栏齐全；
- 可见性符号（`+ - # ~`）正确；
- 关联/继承/聚合/组合/依赖箭头语义正确；
- 继承层级自上而下清晰；
- 标签未遮挡、参数和属性不溢出；
- Multiplicity / role / association 在合适边端附近。

## UML 时序图（`figure_type=sequence`）

- 参与者在同一水平线阵列；
- 每个参与者都有连续 lifeline；
- 消息方向、箭头方向、请求响应关系清楚；
- 消息标签与线路有足够距，不压在 lifeline 上；
- Activation bar 位置合理、嵌套关系不穿插；
- `alt/loop/opt/par` 边界完整，文本不与分隔线重叠；
- 回传箭头样式一致。

## UML 状态图（`figure_type=state`）

- 主链可读，起止（开始）清晰；
- 「关机」不被误标为终态；
- 转移事件、守护条件、动作在对应边上；
- 回边分层走不同通道，不贴边界；
- 同一状态框多条进出边不共用同一锚点。

## 主流程图（`figure_type=flowchart`）

- 必须使用 Visio 风格扁圆起止（开始/结束）；
- 框按文字收紧，字号与框高相称，缩进版心后仍然可读；
- 判断节点与“是/否”在边标签，不得漂浮小文本覆盖主线；
- 回路和失败分支可回收并收敛至结束；
- 平台/系统边界不被线段长距离穿透。

## 运行部署与结构图（`figure_type=architecture`）

- 节点分层可追踪；
- 通信路径方向合理，外部查询线与内部返回线分道；
- 边 label 位置稳定，不与平台/泳道边界重叠；
- 关键路径不得穿过组件内部核心模块体。

## 活动图（`figure_type=activity`）

- 主流程方向明确、决策与汇合可判；
- Fork/Join 通道不混淆；
- 泳道角色与活动归属一致。

## 用例图（`figure_type=usecase`）

- Actor 在系统边界外，Use Case 在边界内；
- <<include>> 与 <<extend>> 方向和虚线正确；
- 边界闭合完整。

## Communication/对象/时间图（`figure_type` 视具体情况）

- 通信图：消息编号与顺序可读；
- 对象图：实例名-类名映射可辨，属性值完整不被裁剪；
- 时间图：时间轴连续且同步，状态线不跳变。
